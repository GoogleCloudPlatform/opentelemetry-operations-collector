# Tango-GBOC smoke test setup

`TestTangoSmoke` (`../tango_smoke_test.go`) installs the packaged
`otelcol-google` service on a GCE VM and appends
`--config=googlecontrolplane:xds://$TANGO_CP_ENDPOINT?gcp.fleet_id=$TANGO_FLEET_ID&region=$TANGO_REGION`
to the service's regular command line: through a systemd drop-in on Linux, and
by editing the service's `ImagePath` registry value on Windows. It then polls Cloud Monitoring until the
collector's self-o11y gauge `prometheus.googleapis.com/gcp.policy.set.active/gauge`
reports the pre-provisioned PolicySet (`gcp.policy.set.id`) at
`TANGO_EXPECTED_REVISION`. The gauge only changes after the collector has
applied (and ACKed) a revision received from the Control Plane, so that point
proves the Control Plane to Data Plane loop.

The test then checks that the two log filter policies are enforced. Because the
Control Plane does not yet translate source policies, the test replaces the
packaged `config.yaml` with a `filelog` receiver that mirrors the PolicySet's
`fileLogSourcePolicy` (same path on Linux, `C:\gboc-smoke\*.log` on Windows, no
parsing, so each line is a string body),
wired through the `googlepolicy` processor to the
`otlp_grpc/default_gcp_destination` exporter generated by the
`googlecontrolplane` config source. After the PolicySet is active, it uploads
[`sample_logs.log`](sample_logs.log), which holds one line that both filters
keep and one line for each filter to drop, then checks that only the kept line
reaches Cloud Logging.

The test assumes a long-lived fleet and PolicySet already exist and have been
rolled out. It never creates, updates or deletes them.

Current resources (project `stackdriver-test-143416`, number `228437877067`,
location `asia-east1`, staging Telemetry Management API, staging Telemetry
Director `staging-telemetrydirector.asia-east1.rep.sandbox.googleapis.com:443`):

| Resource | Name |
|---|---|
| Fleet | `projects/stackdriver-test-143416/locations/asia-east1/fleets/gboc-smoke-fleet` |
| PolicySet | `projects/228437877067/locations/asia-east1/policySets/gboc-smoke-ps` |
| Revision | `projects/228437877067/locations/asia-east1/policySets/gboc-smoke-ps/revisions/75cbca3b` |

The PolicySet body is in [`policyset.json`](policyset.json). It contains a
filelog source policy for `/var/log/gboc-smoke/*.log`, a log transform policy
and two log filter policies, all matching on the log body.
The Control Plane currently translates only `universalPolicies[].logFilterPolicy`
into the xDS `TelemetryCollector` resource, so the collector reports
`policies_loaded: 2`. The test relies on both filter policies.

## Off-GCP X.509 Workload Identity Federation (WIF) setup

To test the off-GCP authentication path (X.509 certificate + WIF + mTLS STS token
exchange with no attached VM service account and `GCE_METADATA_HOST=127.0.0.1:1`),
a separate project outside the `google.com` organization (`gboc-tango-testing`,
number `406580743452`) is used for the Workload Identity Pool and off-GCP test
VMs (`google.com` organization policies restrict external WIF pools/principals).

**The WIF pool and provider below are already created.** They do not need to be
recreated to run the test; see [Recreating the resources](#recreating-the-resources)
only if they are deleted or a new project is used.

| Resource | Name |
|---|---|
| Project | `gboc-tango-testing` (number `406580743452`) |
| Workload Identity Pool | `projects/406580743452/locations/global/workloadIdentityPools/gboc-x509-pool` |
| X.509 Provider | `projects/406580743452/locations/global/workloadIdentityPools/gboc-x509-pool/providers/gboc-x509-prov` |
| Principal | `principal://iam.googleapis.com/projects/406580743452/locations/global/workloadIdentityPools/gboc-x509-pool/subject/gboc-smoke-workload` |

The principal has `roles/logging.logWriter`, `roles/monitoring.metricWriter`,
`roles/trafficdirector.client` and `roles/viewer` on `gboc-tango-testing`.

The CA in the provider's trust store (`CN=gboc-tango-x509-ca`) and the workload
certificate it signed (`CN=gboc-smoke-workload`, `leaf.pem` and `leaf.key`) are
not checked in. Ask the test owner for them. `setup_policyset.sh` refuses to
generate a new CA while the provider exists, because that would replace the
trust store and invalidate the existing workload certificate.

The fleet and PolicySet stay in `stackdriver-test-143416`: the staging Telemetry
Management API cannot be shared outside the `google.com` organization, so it
cannot be enabled in `gboc-tango-testing`. The off-GCP collector subscribes to
the fleet by project number and sends its telemetry to `gboc-tango-testing`,
where the principal can write.

## Recreating the resources

All resources above are pre-created. [`setup_policyset.sh`](setup_policyset.sh)
recreates them if needed. It is idempotent and not run by CI.

```
./setup_policyset.sh PROJECT_ID [LOCATION] [WIF_PROJECT_ID] [WIF_OUT_DIR]
```

| Argument | Example | What it sets up |
|---|---|---|
| `PROJECT_ID` (required) | `stackdriver-test-143416` | Opts the project into the staging Telemetry Management API, creates or updates the fleet and PolicySet, and rolls the latest revision out to the fleet. |
| `LOCATION` | `asia-east1` (default) | Location of the fleet and PolicySet. |
| `WIF_PROJECT_ID` (optional) | `gboc-tango-testing` | Creates or updates the X.509 WIF pool and provider, generates the CA and workload certificates and credential config, and grants the IAM roles above. Skipped when omitted. |
| `WIF_OUT_DIR` | `/tmp/gboc-tango-wif` (default) | Where the certificates, `trust_store.json`, `cert_config.json` and `cred_config.json` are written. Existing certificates are reused. |

With the current values, the script creates or updates:

| Resource | Name |
|---|---|
| Fleet | `projects/stackdriver-test-143416/locations/asia-east1/fleets/gboc-smoke-fleet` |
| PolicySet | `projects/228437877067/locations/asia-east1/policySets/gboc-smoke-ps` |
| Revision | `projects/228437877067/locations/asia-east1/policySets/gboc-smoke-ps/revisions/<new revision>` (printed by the script) |
| Rollout | `projects/228437877067/locations/asia-east1/fleets/gboc-smoke-fleet/rollouts/r-<timestamp>` |
| Workload Identity Pool | `projects/406580743452/locations/global/workloadIdentityPools/gboc-x509-pool` |
| X.509 Provider | `projects/406580743452/locations/global/workloadIdentityPools/gboc-x509-pool/providers/gboc-x509-prov` |

To recreate only the fleet and PolicySet:

```
./setup_policyset.sh stackdriver-test-143416
```

To also recreate the WIF pool:

```
./setup_policyset.sh stackdriver-test-143416 asia-east1 gboc-tango-testing
```

Any PolicySet update creates a new revision. Update `TANGO_EXPECTED_REVISION`
and the revision in the table above to match.

A newly created fleet can take several minutes to become visible to Telemetry
Director. Until then the collector logs
`NotFound desc = Traffic Director configuration was not found`.

## Inspecting the resources

```
P=stackdriver-test-143416
BASE=https://staging-telemetrymanagement.sandbox.googleapis.com/v1alpha/projects/$P/locations/asia-east1
HDRS=(-H "Authorization: Bearer $(gcloud auth print-access-token)" -H "X-Goog-User-Project: $P" -H "X-Goog-Visibilities: TRUSTED_TESTER_COLLECTORS")

curl -sS "${HDRS[@]}" "$BASE/fleets/gboc-smoke-fleet"
curl -sS "${HDRS[@]}" "$BASE/policySets/gboc-smoke-ps"
curl -sS "${HDRS[@]}" "$BASE/policySets/gboc-smoke-ps/revisions/75cbca3b"
curl -sS "${HDRS[@]}" "$BASE/fleets/gboc-smoke-fleet/rollouts"
```

The `X-Goog-Visibilities` header is required. Without it the API answers
`404 Method not visible`.

## Running locally

The test needs a `.deb`/`.rpm` (Linux) or `.goo` (Windows) package of the
collector in GCS. Use a build that includes #768: the Control Plane now sends
the shared `Predicate` matcher proto, and older collectors NACK the filter
policies with `matcher must specify a valid predicate`.

```
cd integration_test/smoke_test
env PROJECT=stackdriver-test-143416 ZONES=asia-east1-a IMAGE_SPECS=debian-cloud:debian-12,windows-cloud:windows-2022 \
  KOKORO_BUILD_ID=local-$(date +%s) TRANSFERS_BUCKET=<bucket> \
  _BUILD_ARTIFACTS_PACKAGE_GCS=gs://<bucket>/<package-dir> \
  TANGO_CP_ENDPOINT=staging-telemetrydirector.asia-east1.rep.sandbox.googleapis.com:443 \
  TANGO_EXPECTED_REVISION=75cbca3b \
  go test -tags integration_test -run TestTangoSmoke -v -timeout 60m ./...
```

### Off-GCP mode

With `TANGO_OFF_GCP=true`, the test creates the VM with no service account and
no OAuth scopes, disables the GCE metadata server for the collector, and
authenticates with the X.509 WIF credentials above. The VM has no credentials
to read GCS, so the test downloads the package itself and streams it and all
other files to the VM over SSH. Off-GCP mode is Linux only for now.

```
cd integration_test/smoke_test
env PROJECT=gboc-tango-testing ZONES=asia-east1-a IMAGE_SPECS=debian-cloud:debian-12 \
  KOKORO_BUILD_ID=local-$(date +%s) TRANSFERS_BUCKET=gboc-tango-testing-smoke \
  _BUILD_ARTIFACTS_PACKAGE_GCS=gs://gboc-tango-testing-smoke/<package-dir> \
  TANGO_CP_ENDPOINT=staging-telemetrydirector.asia-east1.rep.sandbox.googleapis.com:443 \
  TANGO_EXPECTED_REVISION=75cbca3b \
  TANGO_OFF_GCP=true TANGO_PROJECT=gboc-tango-testing TANGO_PROJECT_NUMBER=228437877067 \
  TANGO_WIF_DIR=<directory holding leaf.pem and leaf.key> \
  go test -tags integration_test -run TestTangoSmoke -v -timeout 60m ./...
```

The package must also include `open-telemetry/opentelemetry-collector-contrib#52488`
(X.509 WIF support in `googleclientauthextension`). As of this change, the
test only passes off GCP with two more collector fixes that are not merged yet:
the xDS node ID must name the fleet's project (Telemetry Director otherwise
authorizes federated credentials against the bare collector ID), and the
collector's self metrics need a `cloud.region` when GCE resource detection is
unavailable.
